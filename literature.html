논문 후보 20개를 모두 실행한 것은 아니다. 실제 샘플 비교에는 그림 설명용 Patch-ioner·Florence와 글자 읽기용 PP-OCRv5·EasyOCR를 사용하였다. 네 도구의 역할과 선택 이유, 실제로 만든 실험 도구를 먼저 보면 아래 조사 내용을 이해하기 쉽다.

이번 조사에서 확인한 것

  • 검토한 2026 후보에서 모든 엄격 조건을 충족하는 완성형 솔루션은 확인하지 못하였다.
  • 한국어 OCR, 이미지·영역 설명, 위치를 보존한 근거 결합이 각각 필요한 것으로 정리하였다.
  • 우선 비교 구성은 PP-OCRv5 한국어 인식기 또는 EasyOCR + 이미지 설명기 + 불확실 영역 재확인으로 두었다.
  • 논문 발표, 저장소 존재, 실행 코드·가중치 공개, 실제 추론 성공을 구분하여 기록하였다.
  • 이 페이지는 문헌·공개 상태를 조사한 내용이다. 아래 후보의 로컬 실행 성공이나 대회 성능을 이 페이지에서 입증하지 않았다. 실제 실행·오류·시간은 별도 실험 결과에 기록하였다.

  • OCR에 레이아웃과 읽기 순서를 더해도 사진 속 행동이나 버튼의 실제 목적까지 자동으로 알게 되지는 않는다.
  • 반대로 captioner가 “안내문”이나 “표지판”을 알아보았다고 해서 행사명·날짜·전화번호를 정확히 읽은 것은 아니다.
  • 이 세 역할을 분리해 평가해야 한다.
  • 한국어 문제도 세 층으로 나뉜다.
  • 첫째는 한글 획과 받침을 복원하는 전사, 둘째는 문구와 그림의 위치 관계 및 의미 이해, 셋째는 확인된 사실을 한국어 문장으로 표현하는 일이다.
  • 영어 캡션을 자연스럽게 번역하는 모델은 첫 번째 문제를 해결한 증거가 아니다.

3.1 Patch-ioner: 저비용 지역 설명 기준선

목표
  • 지정한 영역의 특징을 재사용하는 가벼운 설명기를 찾았다.
구조
  • 동결된 시각 backbone의 patch feature를 뽑고, 지정된 영역에 속한 patch들을 모아 region vector를 만든 뒤 text decoder로 설명한다.
  • 서로 떨어진 여러 영역도 모아 설명할 수 있다.
  • 여러 영역을 요청할 때 시각 특징을 한 번 계산한 뒤 재사용하는 것이 장점이다.
  • 다만 patch는 그 patch의 픽셀만 보존한 독립 사진이 아니다.
  • backbone이 섞어 둔 문맥이 포함되고 그 문맥 범위가 사용자 의도에 맞춰 바뀌지는 않는다. 저자 프로젝트[45]
확인 결과
  • 논문: One Patch to Caption Them All: A Unified Zero-Shot Captioning Framework.
  • CVPR 2026.
  • 실제 공개 상태는 양호하다.
  • 설치 패키지와 추론 예제가 있고 Talk2DINO+DeCap, CapDec, ViECap, MeaCap 모델을 Hugging Face로 제공한다.

7.1 최종 문제는 기존 alt의 품질 판정이다

  • 공식 문제에서 최종 과업은 alt를 새로 생성하는 것이 아니라, 주어진 alt를 7범주로 판정하는 것이다.
  • 입력에는 이미지, 기존 alt_text, 페이지 제목, 인접 문맥, 링크 여부와 목적지 등이 포함된다.
  • description은 이 판정에 공급할 독립적인 시각 근거다. 2026-09-21 수정된 공식 설명은 샘플 299쌍, 전체 공개 데이터 3,000쌍을 안내하며 비공개 홀드아웃 분할로 평가한다고 명시한다. 공식 문제[93] 공식 상세 설명[94]
  • 출력은 적절·무의미형·파일명형·중복형·장식오용형·불충분형·무관형 중 하나이며 record_id,label 두 열 CSV로 제출한다. 7범주 macro-F1와 적절/부적절 이진 F1을 가중 합산한다.
  • 두 F1의 정확한 가중치, 이진 positive class, 외부 인터넷·API 허용 범위, 실행 환경·시간·메모리 제한 및 제출 운영의 세부 관계는 확인한 설명만으로 확정하지 않는다.
  • 접근 방법의 자유를 실시간 브라우징 허용으로 확대 해석하지 않는다.
  • 돋보기 그림을 “원과 손잡이”라고 설명하는 것은 시각적 사실이지만 검색 버튼의 alt는 검색 동작을 전달해야 한다.
  • 장식 이미지나 주변 문구와 중복되는 이미지에서는 긴 설명이 오히려 부적절할 수 있다.
  • 대회 판정에는 동봉 가이드라인을 우선 적용하고 W3C 자료는 원리의 보조 근거로 사용한다. 기능성 이미지[95] 텍스트 이미지[96] alt 판단 흐름[97]

7.2 로컬 가이드라인을 적용할 때의 판정 경계

  • 샘플에 동봉된 라벨링 가이드라인 v0.2(2026-08-26)는 alt 속성이 없는 이미지와 alt가 빈 문자열인 이미지를 구분한다.
  • 전자는 범위 밖이고 후자는 포함한다.
  • 같은 링크 안에 동일 정보를 전달하는 텍스트가 있으면 반복 alt는 중복형일 수 있지만, 이미지가 링크의 유일한 콘텐츠이면 목적지를 설명하는 alt가 적절할 수 있다.
  • 긴 텍스트 이미지에서는 핵심 문구와 상세 위치 안내를 함께 제공하는 방식도 인정한다.
  • 글자 수나 오탈자·비문만으로 품질을 판정하지 않는다.
  • 복수 오류의 우선순위는 파일명형 → 무관형 → 무의미형 → 장식오용형 → 중복형 → 불충분형이다.

  • 핵심 문구 인정 범위와 longdesc·aria-describedby 처리는 문서의 미결 항목을 함께 확인해야 한다.
  • 가이드라인의 문맥 부족 시 원 페이지 방문 허용은 라벨러 절차에 관한 문구다.

7.3 제안 파이프라인

  1. 원본과 입력을 고정한다.
    • 원해상도, 비율, 투명 배경, 이미지 hash와 metadata를 보존한다.
    • extraction에는 기존 alt·정답 label을 넣지 않는다.
  2. 한국어 OCR로 문자 근거를 만든다.
    • 문자 box·원문·confidence·block·읽기 순서를 남긴다.
    • PP-OCRv5와 EasyOCR를 동일 표본에서 먼저 비교한다.
  3. 전체와 선택 영역의 시각 사실을 추출한다.
    • 사진·아이콘 영역의 객체·속성·행동을 설명하고 box ID를 연결한다.
    • 글자가 많은 영역에서는 captioner의 임의 전사보다 OCR 원문을 보존한다.
  4. 근거를 합치되 출처를 유지한다.
    • OCR와 시각 모델이 서로 다른 문구·대상을 말하면 덮어쓰지 않고 충돌로 표시한다.
    • 좌표를 이용해 제목·사진·버튼 관계를 연결한다.
  5. 필요한 영역만 재확인한다.
    • 작은 글자, 중요한 숫자, 모델 간 불일치에만 원본 crop·다른 OCR·추가 caption을 적용한다.
    • 재검사 횟수와 비용을 기록한다.
  6. Gemma가 근거와 metadata로 alt를 판정한다.
    • 관찰 사실과 문맥 추론을 구분한다.
    • 날짜·금액·고유명사를 그럴듯하게 복원하지 않는다.
    • 최종 출력은 대회 라벨 규칙에 맞춘다.

7.4 Gemma12B-QAT와 실행 자원의 역할

  • Gemma는 우선 텍스트 근거와 metadata를 읽는 판정 모델로 배치한다.
  • 이미지 encoder를 직접 쓰는 구성은 별도의 VLM 실험으로 분리한다.
  • QAT나 낮은 가중치 정밀도만으로 전체 메모리가 같은 비율로 줄어든다고 가정하지 않는다.
  • vision encoder, KV cache, 입력 해상도, 출력 길이와 runtime 메모리가 추가된다.
  • 6GB GPU에서는 OCR 두 개와 captioner·Gemma를 한꺼번에 적재하기보다 단계별 순차 실행과 CPU fallback을 비교하는 것이 현실적이다.
  • 이는 자원 운영 제안이며 현재 속도 보장이 아니다.
  • CausalLens·ECRD·FLB 같은 Transformers 내부 개입을 Gemma GGUF/llama.cpp에 그대로 꽂을 수 있다고 표기하지 않는다.

  • 사진, 글 중심 포스터, 사진+한글, 아이콘·로고, 표·도식, 저해상도, 빈 alt·기능성 레코드를 고정하여 비교한다.
  • 성공 사례 몇 장은 작동 확인이며 전체 299건이나 3,000건의 성능 증명이 아니다.
  • 이미지 hash/perceptual hash, 페이지와 도메인으로 중복을 확인하고 같은 이미지·페이지가 개발과 검증에 동시에 들어가지 않게 그룹으로 나눈다.
  • 동일 이미지라도 기존 alt와 문맥에 따라 라벨이 다르므로 이미지 중복과 레코드 중복을 혼동하지 않는다.
  • prompt·crop 기준·OCR 임계값을 수정한 표본은 개발셋으로 취급하고 검증 전에 설정을 고정한다.
  • 설명 추출에는 이미지와 처리 파라미터만 넣는다.
  • 기존 alt·page title·context로 이미지를 미리 설명하게 만들면 독립적인 extraction 평가가 아니다.
  • 반면 최종 판정기에는 대회가 제공한 alt와 metadata를 동일하게 제공한다.
  • 정답 label·샘플 해설·검색된 정답을 판정 입력으로 가져오지 않는다.

7.7 Playwright·웹 검색은 선택적 두 번째 실험

  • Playwright는 웹 문맥을 가져오는 도구이며 품질 검증 논리 자체는 아니다. 1차 구성은 제공 이미지·metadata만으로 재현 가능하게 만들고, 외부 인터넷 허용 여부가 확인된 후 웹 근거를 켠 별도 실험을 한다.
  • 현재 페이지는 데이터 수집 시점과 달라질 수 있어 조회일, URL, 보존한 HTML 및 인용 위치를 기록해야 한다.
  • 검색으로 얻은 문맥을 이미지에서 직접 보인 사실과 별도 필드에 저장한다.
  • 같은 alt를 검색해 다시 정답 근거로 삼거나 공개 라벨·참가자 예측을 가져오는 흐름은 차단한다.
  • 검색 성공률·시간·비용까지 포함해, 최종 판정의 개선이 실제로 있는 경우에만 채택한다.
